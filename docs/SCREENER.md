## 1. 这套东西是什么

两阶段漏斗：先用多因子把全池压成少量候选，再对候选深度分析。

```
阶段一  量化初筛（screener_engine）
        ├─ 数据层：tradingagents.dataflows.stockstats_utils.load_ohlcv
        └─ 打分：四维 GARP 截面百分位
              ↓  候选（默认 Top 3~10）
阶段二  深度分析（二选一）
        ├─ wb_deep_dive.py   零成本：采证 + 顶层模型按 FRAMEWORK.md 推理
        └─ smart_screener.py 付费：TradingAgentsGraph 多智能体会诊
```

**入口**：

```bash
# 只看量化榜单 + 导出 CSV（不花钱、不调 LLM）
python quant/smart_screener.py --pool nasdaq --skip-agent
python quant/wb_deep_dive.py  --pool nasdaq --top 3 --no-social   # 采证 + 导出 CSV

# 因子有效性回测 / 衰减监测
python quant/factor_backtest.py
python quant/factor_backtest.py --watch      # 有告警时退出码=2，可接 CI
```

**首次运行预热**：`load_ohlcv` 逐票缓存约 43s 建立，之后 `force_refresh` 约 18s、命中日内缓存 0s。

## 2. 打分模型

综合分 = 质量 35% + 估值 30% + 成长 30% + 趋势 5%（权重见 `FACTOR_WEIGHTS`；
趋势档于 2026-10-02 由 20% 降为残差，依据见下「权重档案」）

| 档 | 子因子 | 说明 |
|---|---|---|
| 质量 | ROE(0.4) + 净利率(0.4) + 低负债(0.2) | 加入负债维度以降低 ROE 与净利率的共线性 |
| 估值 | PE 截面百分位 | 越便宜分越高；**亏损/缺失 PE 记 0** |
| 成长 | 营收同比增速百分位 | — |
| 趋势 | 60日动量(0.6) + 均线多头(0.25) + RSI 区间(0.15) | 三个子分数各自归一化后加权 |

所有因子先转成**截面百分位（0~100）**再加权。

### 权重档案

```python
from quant.screener_engine import run_quant_screening, WEIGHT_PROFILES

run_quant_screening(tickers)                                  # 默认 = quality（趋势 5%）
run_quant_screening(tickers, weights=WEIGHT_PROFILES["no_trend"])
```

| 档案 | 质量 | 估值 | 成长 | 趋势 | 适用 |
|---|---|---|---|---|---|
| `quality`（默认） | 0.35 | 0.30 | 0.30 | **0.05** | 趋势档压到残差 |
| `garp`（旧默认） | 0.30 | 0.25 | 0.25 | **0.20** | 四维均衡；保留作对照/回退 |
| `no_trend` | 0.35 | 0.35 | 0.30 | **0.00** | 完全不想要动量暴露 |

**2026-10-02：默认档由 `garp` 改为 `quality`（趋势 20% → 5%）。**
2026-09 时的立场是「**不**默改 `garp`」，理由是「49 期样本统计功效不足，拿一次不显著的
测量去改默认权重正是过拟合陷阱」。**那个立场在当时是对的**，不必否定 —— 但它依赖
「样本测不出」这个前提。样本扩到 **311 期 / 26 年**后，趋势档 IC 的 95% 置信区间收到
约 ±0.01，前提由「测不出」变为「**测出了零**」，故改默认（详见
`screener_engine.FACTOR_WEIGHTS` 上方注释，那里是权威）。

⚠️ **反过拟合的纪律没有放松**：判据取自 26 年全样本，**不是**近期窗口 ——
近期窗口的 trend IC 反而是**正的**（近 12 期 +0.0096），按近期拟合应该**加**权。
任何后续再校准（包括你自己）都**不得**用「最近 N 期」反推权重。

## 3. ⚠️ 能力边界（最重要的一节）

### 3.1 因子验证状态：四个因子全部已回测，**无一统计显著**

> **权威数值在 `screener_engine.FACTOR_VALIDATION`** —— 程序每次运行都会把它打印出来，
> 那里改了本节不必跟。本节只给结论与读法（**数据日期：2026-09-20 实测**）。
> 两处各写一遍必然漂移 → 发现数值对不上时，**以代码为准**。

**口径**：SEC EDGAR 时点基本面，2009-01 ~ 2025-01，**17 个不重叠年度观测**
（前瞻 252 日 = 调仓 252 日）、行业中性化。**两个宇宙都跑过，结论一致**：

| 因子 | 纳指100（84 只截面）IC / t | 标普500（436 只截面）IC / t |
|---|---|---|
| 质量(ROE+净利率) | −0.0436 / −1.17 | −0.0301 / −0.92 |
| 估值(低PE) | −0.0503 / −1.26 | −0.0344 / −1.08 |
| 估值(低PB) | −0.0284 / −0.78 | −0.0533 / −1.39 |
| 估值(PE+PB双低) | −0.0472 / −1.17 | −0.0532 / −1.31 |
| 成长(单季营收同比) | +0.0072 / 0.24 | −0.0170 / −0.51 |
| 成长(3年营收CAGR) | +0.0164 / 0.49 | +0.0334 / 0.94 |
| 趋势(价格类，**311 期**月频) | **−0.0009 / −0.08** | —（旧 49 期读数 −0.0037 / −0.11） |

**怎么读**：

- **四档全部不显著**（|t| 最大 1.39）⇒ 对**基本面三档**，正确表述是「**尚未证明有选股
  能力**」，**不是**「已证明无用」—— N=16 的统计功效太低，即使有真实效应也检测不出来。
- ⚠️ **但趋势档不一样**：311 期（26 年）把它 IC 的置信区间收到约 ±0.01 ⇒ 它是**被排除**
  而非「测不出」。这是四档中**唯一**功效足够下结论的一档，所以 2026-10-02 只降它 ——
  这不是「顺手把所有不显著的都砍掉」，而是**只动证据最硬的那一档**。
- **换池救不回来**：截面从 84 放大到 **436（5.2 倍）**，|t| 仍全 < 1.4。
  ⇒ 瓶颈是**独立年度观测数**，加标的、加因子都改不了。
- **估值维度加 PB 也没用**（低 PB −0.0533、PE+PB 双低 −0.0532，都不显著）。
  ⚠️ 但 PB 与 PE 的相对强弱**两个宇宙里相反**（纳指100 上 PB 更弱）⇒ 差异落在噪声内，
  **别把单次测量当定论**。
- **成长维度改口径有效但不够**：单季营收同比 → **3 年营收 CAGR** 后 IC 转正、
  且两宇宙符号一致，但 t 仍只有 0.94。
- ★ **必须做中性化前后对照**：3 年 CAGR 的**原始 IC 在标普500 上高达 +0.0824**，
  中性化后塌到 +0.0334 ⇒ **一半以上是行业暴露的伪装**。评估任何新因子都先做这一步。
- 这组用**不重叠**窗口 + 行业中性化，所以不再是口径问题。
  （早期跑出的「12 个月 IC −0.10、t −7.5」是**窗口重叠 12 倍**的假显著，
  已作废 —— 脚本现在会自动检测并警告。）
- ⚠️ **幸存者偏差**：股票池是「今天还活着的成分」，已退市者不在其中
  （`--include-delisted` 可部分缓解）。
- ⚠️ 未计交易成本；基本面按季更新，月度调仓时多数月份因子值不变。

**⇒ 请把榜单当作「结构化研究漏斗」，而不是「有预期超额收益的排序」。**
**⇒ 也不要再往打分 / 因子上继续投入** —— 限制来自数据源的年度观测数，
继续调参只会增加拟合噪音。判断应交给 12 角色深度尽调。

### 3.2 时点基本面从哪来（`edgar_fundamentals.py`）

由 SEC EDGAR 的 XBRL `companyfacts` 提供**时点键**：每条记录带 `filed`（申报日），
即「在 T 日市场知道什么」= `filed <= T` 中 `end` 最晚的那条。

```
CIK 映射  sec.gov/files/company_tickers.json
历史财报  data.sec.gov/api/xbrl/companyfacts/CIK*.json   （实测 AAPL 4 MB / 2.2s）
```

102 家合计约 **342 MB**（`~/.tradingagents/edgar/`）。

**EDGAR 三个数据坑、UA 要求、缓存按季度命名 + `prune_cache()` 等规则，
见 `DOMAINS.md` → 量化选股子系统 / SEC EDGAR**（本文件不逐字重复）。

监控手段：`edgar_fundamentals.cache_size_mb()` / `prune_cache()`。

### 3.3 趋势档的符号会随回看窗口漂移

同一批数据、只换回看窗口：

| 因子 | 近6期 | 近12期 | 近18期 | 近24期 |
|---|---|---|---|---|
| 60日动量 | −0.0874 | **+0.0505** | −0.0049 | +0.0058 |
| 趋势综合分 | −0.0985 | **+0.0426** | −0.0216 | −0.0051 |

**只差 6 个月，符号就完全翻转。** 这不是「某年好某年差」，而是换一个窗口结论就变号 ——
说明该信号**不稳健**，任何基于它的固定权重都缺乏依据。

**处置方式**：不要试图用近期窗口反拟合权重（那是过拟合）。要么接受它、
要么用 `weights={"trend": 0.0}` 停用该档。

### 3.4 其他已知偏差

| 偏差 | 影响 | 现状 |
|---|---|---|
| **幸存者偏差** | 已退市标的（WBA/ANSS/KCG/EA）不在池中，回测偏乐观 | 无法消除，只能声明 |
| **股票池静态** | 纳指每年 12 月重组 + 季度再平衡 | 见 `DOMAINS.md` → 量化选股子系统 / 股票池（Wikipedia 同步与静态兜底） |
| **盘中未收盘 bar** | 北京时间上午运行 = 美东盘中，最后一根 K 线是实时快照 | 输出的 `last_bar` 字段可核对 |
| **治理风险** | 审计意见、财务造假、股权质押均不可得 | 结构性盲区 |
| **★ 负税抬高净利** | 一次性税收收益会**同时**顶高净利率与 ROE ⇒ **「ROE ≥ 20% 且 净利率 ≥ 15%」这类阈值门槛拦不住**。实测 DUOL 税收收益占净利 **56%**（报表 PE 16.0x → 正常化 **40.1x**）、ACAD 占 **64%**（12.0x → **38.6x**）—— 两只都曾是榜单前列 | ✅ 已由 `_verify_earnings_quality.py` 的**硬闸门**拦截；判据是「税收收益占净利的比例 ≥ 20%」，**不是「税率是否 < 0」**（后者会把 −0.1% 的噪声也判死） |
| **正常化偏离（非负税类）** | 除负税外，其他非经常项同样会扭曲报表 PE。实测 LAUR 17.7→27.0x、INCY 19.7→23.7x、ECPG 8.2→10.0x | ✅ 同上工具的第二道硬闸门（正常化 PE ≤ 1.2× 报表 PE） |

## 4. 数据层约定

**使用 `load_ohlcv`，不使用 `yf.download` 批量接口**：Yahoo 对高并发批量请求限流，
失败随机 → 榜单**不可复现**。逐票 `load_ohlcv` + 并发 5 即 96/97、失败率 1.0%；
引擎在其上加**受限并发(5) + 失败补拉 2 轮**（`load_ohlcv` 自带缓存、退避重试、防前视偏差）。

**限流机制、静默失效排查、`CACHE_SCHEMA_VERSION`、缓存只存子分数等细节，
见 `DOMAINS.md` → 量化选股子系统 / 数据层 与 缓存与工程。**

### 文件命名约定

| 类型 | 命名 | 理由 |
|---|---|---|
| 量化数据快照 | `radar_<pool>_<YYYY-MM-DD>.csv` | 按天走缓存 ⇒ 同日重跑是**逐字节相同**的数据，用时间戳会堆重复文件 |
| 会诊报告 | `screener_<pool>_<时间戳>.md` | 记录「这一次会诊了谁」，有历史价值 |

## 5. 维护节奏（**这套东西不是一次修好就永久**）

### 5.1 哪些不会过期

以下修的是**逻辑正确性**，不随市场变化：CSV 带 UTF-8 BOM、失败可见不静默吞错、
缓存键含标的指纹、亏损公司估值分给 0、不伪造 200 日均线、失败原因准确、
`load_ohlcv` 作为数据抽象层（上游维护限流/缓存逻辑）。

### 5.2 哪些会衰减，需要定期复核

| 项 | 为什么会变 | 建议节奏 |
|---|---|---|
| **因子权重** | 实测逐年翻符号 | 季度 |
| **`MAX_WORKERS = 5`** | 是对 Yahoo 限流容忍度的**外部假设**，会变 | 季度（若剔除率异常升高，先怀疑它） |
| **阈值**（ROE≥15%、`MIN_BARS=60`） | 经验值，从未校准 | 年度 |
| **`yf.Ticker().info`** | Yahoo 改接口就断；且无历史，断了查不出从哪天开始错 | 每次运行留意字段缺失率 |
| **股票池** | 指数重组 | 每年 12 月 + 每季度 |
| **`factor_backtest.py` 的基线** | 需累积更多期数才有统计效力 | 季度跑一次 `--watch` |

### 5.3 推荐的季度 routine

```bash
python quant/factor_backtest.py --watch   # 退出码 2 = 有告警，需要看一眼
```

`--watch` 会：
1. 用**非重叠双样本 t 检验**对比「近 12 期」与「此前基线」
2. 做**窗口敏感性检验**（近 6/12/18/24 期符号是否一致）
3. 把结果**累积**到 `reports/factor_ic_history.csv`
4. 有强告警或符号漂移时返回退出码 2

**设计要点**：它只在符号翻转**且统计显著**（t≥2）时强告警；仅翻转但 t 很小
只作提示 —— 否则会在纯噪声上持续误报。

### 5.4 再校准怎么改

**改配置，不改代码**：

```python
from quant.screener_engine import run_quant_screening
# 停用未经验证且不稳健的趋势档，把权重让给基本面
df = run_quant_screening(tickers, weights={
    "quality": 0.35, "value": 0.35, "growth": 0.30, "trend": 0.0,
})
```

改完记得更新 `FACTOR_VALIDATION`（在 `screener_engine.py` 顶部），
让验证状态与权重保持一致。

## 6. 故障排查

| 症状 | 首先怀疑 |
|---|---|
| 剔除率突然升高 | `MAX_WORKERS` 触发了限流 → 降到 3 试 |
| 某标的持续「无行情数据」 | 是否已退市（`load_ohlcv` 会给出最后交易日） |
| 输出表格全是「…」 | 终端宽度；`smart_screener` 已显式放宽到 200 列 |
| Excel 里中文乱码 | CSV 是否带 UTF-8 BOM（用 `export_radar_csv` 导出即可） |
| 榜单每天不同 | 检查是否有标的被随机丢弃（看 `failed_records`） |
| 测试失败 | `python -m pytest -m unit`（首次需 `pip install -e ".[dev]"`） |
