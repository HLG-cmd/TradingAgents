## 铁律（全部踩过）

### 1. 时点闸门是第一道（最重要）
**期权链只在美东 09:30–16:00 实时刷新**；盘前/盘后拿到的是**残留快照** —— `bid`/`ask` 都 >0、格式合法，但 `lastTradeDate` 可能过时数周。
⇒ **下结论「某源系统性坏了」前，必须至少换一个时点复测。**（此错犯过两次）
⚠️ 「单边 OTM put IV ≈ 22.4%」已作废，严禁引用。

★★ **2026-09-22 修正：盘后的「残留快照」有三种形态，判据必须是「双边报价 ∩ 新鲜成交」——只看 `lastTradeDate` 会误判。**

| 采集时点（美东） | 实测例 | 链的状态 | 是否可用 |
|---|---|---|---|
| 收盘后数小时内（约 16:00–21:00） | GOOG 20:45；NDX(QQQ) 20:49 | **当日收盘快照**（`lastTradeDate` 众数=当日；「双边报价 ∩ 成交≤5 天」样本 1474 / 5673） | ✅ 可用（等级 FULL） |
| **凌晨 / 次日盘前** | **NFLX 02:51** | 报价簿已清空（bid/ask 归 0），只剩**去年 10~11 月的过期挂单**（有双边报价的合约 `lastTradeDate` 全落在 2025-10~11）；**当日成交的合约反而没有双边报价** | ⛔ **不可用**（等级 NONE，属真实缺口） |
| 美东 09:30–16:00 | 9/17 轮 | 实时 | ✅ 可用 |

⇒ **判据（两条都要）**：
① `lastTradeDate` 的**分布**是否集中在最近一个交易日 —— **必要不充分**（NFLX 轮众数就是当日 1,167 条，链仍不可用）；
② 「**有双边报价**（`bid>0` 且 `ask≥bid`）」∩「**成交 ≤5 天**」的交集是否为 0 —— **交集为 0 即判定不可用**。
⇒ 工具：`wb_analysis/_probe_option_freshness.py`（分布）+ **`wb_analysis/_probe_option_dual_quote.py`（交集，最终依据）**。
⇒ 盘前/凌晨采集时，**期权维度必须作为「真实缺口」写入报告，并禁止任何角色引用 IV / 偏斜 / P-C / OI**；
替代读数只有 §12 的 ^VIX/^VXN（须声明是前瞻 IV、不可线性换算）。
⇒ 该案例同时是 **A 类缺口**（上游此刻确实不提供可用报价），**不是**阈值误伤、也**不是**采集器 bug
—— 「必须在美东盘中采集」这条约束的直接后果。

### 2. 三道闸门顺序不可颠倒：时点 → 时间戳 → 数值
| 顺序 | 闸门 | 管什么 |
|---|---|---|
| 1 | **时点** | 采集是否在数据源刷新时段内（★★★ 最易漏；盘前快照数值再漂亮也是垃圾）|
| 2 | 时间戳 | 单样本 `lastTradeDate` 新鲜度（**≤5 天的闸门拦不住 4 天前的残留快照** ⇒ 看分布）|
| 3 | 数值 | IV∈[5%,120%] 等 —— **拦不住「数值正常但过时」** |

盘前快照的时间戳**内部自洽**（全是上一交易日收盘那一刻），逐样本看都「没过期多久」，整体却已隔一整个交易日 —— 只有时点闸门能识别。
**排查手法**：通道「有数据但结论荒唐」→ 先打印采集时点 → 时间戳分布 → 最后才怀疑阈值。

### 3. 静默失败（共同特征：报成功 + 外观正常 + 模型读到合规文本而非缺失标记）
根因同一个：**判据写错 ⇒ 闸门该放时误拒/该拒时误放 ⇒ 失败不可见**。
| 形态 | 为什么静默 |
|---|---|
| StockTwits 用非浏览器 UA ⇒ 403 | 「优雅降级」**返回占位串不抛异常** |
| `_safe_call` 只认 `DATA_UNAVAILABLE` 前缀 | 占位串走普通返回路径 ⇒ **「假绿」**：N/N 里藏空通道 |
| `get_current_date()` 用本机时区 | 扣留时返回语气正常的合规声明 ⇒ **整块估值快照被扣留** |
| `get_fundamentals` 报 `ok` 但 **§3 整节为空**（vendor point-in-time 拒答）| 健康度只统计「调用是否成功」 |

★ **验收规程**：① 不满足于「N/N 全绿」，**打开关键通道看一遍**（情绪源、估值快照、期权等级最易假绿）；
② 非全绿走缺口三分类；③ **凡「有内容但像模板声明」的通道，先怀疑参照系写错**。
⇒ §3 为空时生成 `<T>_<date>.supplement.md`（直接 `yfinance.Ticker(...).info` + 报表自算）作一等证据源。

### 4. 当日 bar 滞后造成的「双口径」
yfinance 日线在收盘后约 4.8 小时仍不发布当日 bar；**Nasdaq 官方 EOD 同样止于前一日**（2026-09-22 实测复核）⇒ 全市场层面滞后。

| 口径 | 覆盖 |
|---|---|
| **T−1** | 行情序列、**全部技术指标**、收益/均线/布林/ATR 基准 |
| **T** | 实时字段、**估值快照**、期权链 spot、新闻「今日涨跌幅」|

**三条必写声明**：① 指标用 T−1、最新价与估值倍数用 T，**不可混用**；
② **`PE×EPS = latest_close` 自洽校验可能失败 —— 这是正确行为不是错误**，必须解释而非掩盖
（快照定价于 T 的实时价，日线止于 T−1；实测 GOOG `17.596×19.94=350.87` vs 日线末 344.41，就是 9/21 vs 9/18）；
③ 均线/布林/ATR 只有 T−1 值，用于 T 日「是否站上 50 日线」属**参照而非精确结论**。
- **交叉核验**：期权链 `spot` 与 `regularMarketPrice` 互证（**同源，不算独立核验**）；媒体报价可能差几美分 ⇒ 以实时字段为主口径并披露媒体值。
  独立第三方常不可得 ⇒ 声明「不可独立核验」，**不要换源再报一次**。
- ⚠️ **跨报告横向对比不可直接相减**：采集时点不同 ⇒ 指标差一个交易日。
- ⚠️ **「指标比价格晚一天」曾被误判为「stockstats 固有行为」** —— 真因是 `_compact_series` 用 `kept[-5:]` 取到窗口内**最旧**的 5 天（`get_indicators` 输出是**新→旧**）。已按日期显式降序修复。
  ⇒ **凡看起来像「数据源固有行为」的系统性滞后，先怀疑自己的排序/切片，不要先写进铁律。**
- ⚠️ **§1 的 `close` 是复权价（`history()` 默认 `auto_adjust=True`），§3/§13 的现价是未调整价**
  ⇒ 「52 周高」有两套（GOOG 实测 复权 403.96 / 快照 404.47，差 0.51 = 窗口内累计股息）；
  与 Nasdaq 官方 API 逐条对照时，**除息日之前的所有 bar 会恒定低一个季度股息**
  （GOOG 2026-09-04 除息 0.22 ⇒ ≤09-03 各 bar 低 0.220×k，该日及以后逐字一致）。
  ⇒ **技术指标基于复权序列是正确的**；引用「距 52 周高/低」必须声明用哪套。诊断脚本 `wb_analysis/_rv_and_adjust_probe.py`。
- ⚠️ **§1 的 volume 四舍五入到百位**（偶有个别日与官方差 0.19%）⇒ 量能引用遇到两源不符时注明。

### 10. 数据缺口三分类（凡写「该项数据缺失」前必做）
混淆会造成两个反向错误（把可修项写成缺口 / 把真不可得当 bug 反复修）。

| 类 | 含义 | 判据 | 处置 |
|---|---|---|---|
| **A** | 上游真实未发布 | 绕过本项目直连上游仍无 | 声明缺口 + **找替代通道** |
| **B** | 阈值误伤 | 放宽闸门后正常且量级合理 | **修闸门**，禁写成缺口 |
| **C** | 采集器 bug | 原始接口有、证据包里没有 | **修代码** + 加回归检测 |

**设任何质量阈值前先测三个数**：垃圾值上界、真实值下界、数量级差 —— 阈值不落在中间＝没设。
（反例：期权 IV 闸门曾设 2.0，而垃圾区 0.001%~0.4%、真实 ≈20% ⇒ 形同虚设；改 5.0 才有效。）

### 11. ★★★ 聚合口径：单只坏值摧毁全表
**凡 `Σ(市值 / 比率)` 形式的聚合，分母必须设「合理区间」，不能只判正负。**
BRK-B 的 `priceToBook` = 0.000975 ⇒ 隐含净资产占全样本 **98.89%** ⇒ 聚合 PB 变 0.06、ROE 变 0.27%（应为约 5 与 18~24%）。
**两个数字都不越界、不报警**，只是「偏得离谱」。**样本越大越容易踩到**（NDX 101 只没踩到，SPX 503 只踩到）。
- **修复**：`PB∈[0.2,1000]`、`PS∈[0.02,5000]`（只额外剔 3 只，市值留存 98.4%）。PB 分位 P1=0.8146 ⇒ 阈值落在 (0.001,0.81) 结果一致。
- **排查判据**：聚合值落在常识区间外时**先做「单只贡献度排序」**，不要先怀疑阈值或换源。
- ⚠️ 负 PB（权益为负）本就被 `>0` 排除，属正确行为；真正需要闸门的是「**极小正值**」这一档。

### 12. 25Δ 偏斜有两个合法口径，数值不同，不可混用
| 口径 | 定义 | 结果 |
|---|---|---|
| **区间中位数（主口径）** | `\|Δ\|∈[0.20,0.30]` 内全部合格合约 IV 的中位数作差 | +6.93pp |
| 单点（备用） | `\|Δ\|` 最接近 0.25 的单个合约作差 | +3.56pp |

⇒ 单点口径**对采集时点敏感**；**报告一律用主口径并声明口径与样本数 n**，不得引用单点数值。
- 偏斜随期限单调递减（近月约 +3.6pp → 119 天约 +1.9pp）是典型期限结构，**可排除「单一事件脉冲」**。

- **偏斜历史序列不存在**（yfinance 无历史期权链）⇒ 严禁描述为「极端/异常偏高/已回落」。

- ⚠️ 近月 25Δ 常只有 n=1~3 个合格合约 ⇒ **据其下强结论在统计上无效**，必须随结论披露 n。

### 15. 本机工具链
- bash **无 `sort`**；`timeout` 是 Windows 命令；`/tmp` 会变成 `D:\tmp`；`find` 被 Windows find.exe 抢占 ⇒ 用 Python `os.walk`。
- **safe-delete 钩子**：对目录的删除/移动 fail-closed 拦截；**逐文件 `os.remove()` 可行**，再自深到浅 `rmdir`；被进程占用的文件先 `taskkill`。**不要去绕过它。**
- ⚠️ **`wc -m` 在本机 Git Bash 下数的是「字节」不是「字符」**（非 UTF-8 locale）⇒ 含中文的文件会**虚报 2~3 倍**（实测 `wc -m` 报 25,403 而 Python `len()` 只有 11,693）。
  ⇒ **凡核对文本长度，一律用 Python `len(text)`**；让子智能体自检长度时必须写明这一点，否则它们会「以为自己达标了」而实际偏短。

### 16. ★★★ 分项之和 ≠ 自己写的合计 ⇒ 分项被反向编造
实测：5 个分项全错但合计全对，且分项自身求和连它自己写的合计都对不上 ⇒ 分项是为「配上正确的合计」**倒推伪造**的。
**偏差可以来自精度/时点，自相矛盾只能来自编造** —— 这比「数值偏高偏低」硬得多。
⇒ 任何聚合类数字（行业权重、Top-N 权重、分部收入）必须验证两件事：
① 每个分项能在原始源逐项找到；② **分项求和 === 自己写的合计**（`_audit_values.py` 已内置）。

### 17. ★★★ cashtag 主体判定必须取「第一个」
用「消息是否包含 `$QQQ`」判定 ⇒ 错。改用**首个 cashtag** 后：名义 6:6（持平）→ 主体 3:5（偏空），**直接翻转结论**。
⇒ **取消息中出现的第一个 cashtag；它是本标的才算主体。**
⇒ 报告**两套数字都给**。「无标签」≠「跑题」（抓取流本身按标的过滤），但仍不得据此赋方向。
- ⚠️ **未打标签的消息不得赋方向后计入多空比**，但可定性描述；大量 unlabeled 常意味着**分歧明显**。

### 18. ★★ 同一目录内可能有两种行尾 —— 编辑前必须探测
实测 `0_brief.md` 是 CRLF、`_constraints.md` 是 LF。
**症状**：用 LF 的 `old_string` 去改 CRLF 文件，**编辑工具回报「成功」但内容零变化**。
⇒ **改写前探测行尾，改写后回读验证，不得信任编辑回执。**
⇒ 可靠做法：按行尾自适应（`SEP = "\r\n" if "\r\n" in text else "\n"`）再 `write_bytes`。⚠️ 别写死 `split("\r\n")`。

### 19. ★★ 子智能体报「网络失败」可能是假失败 —— 先验产物，别急着重跑
断连常发生在**产物已落盘之后**，失败通知只是回传阶段中断（实测 `bear.md` 75KB 完整、审计零问题）。
⇒ **第一步查产物完整性（字节数 + 审计 + 尾部是否截断），不要盲目重跑** —— 重跑会覆盖一份已完成的几十 KB 报告。
⇒ **判据是产物审计，不是失败通知本身。** 只有产物缺失/截断/审计不过才需重跑。
★ **2026-09-21 再应验（429 配额耗尽）**：研究经理报 `failed: 429`，但 `manager.md` **已完整落盘 28KB 且逐项通过契约校验**
⇒ 429 是在**「写完文件之后、回报之前」**触发的。**验完直接采用，不要重跑**。
- **配额耗尽处置顺序**：① 先验产物（往往已跑完）→ ② 等配额重置 → ③ 换模型（跨角色模型不一致，须声明）
  → ④ **最差是主智能体代写角色**：那会**塌掉「角色独立判断」这个前提**，等于自己给自己的论证打分，**必须先告知用户并获同意**。

### 20. ★★ 审计工具必须有「文档描述 vs 真实污染」的判别力
豁免表必须覆盖三类「合法提到旧值」的语境：**修正**（实为/应为/误值/改为）、**归档**（旧稿/旧版/stale）、**复盘**（X.md 写/曾写/误报/错报）。
⇒ **验收标准（改豁免表后必测）：文档目录全绿 + 真实陈旧文件仍全部命中，两者必须同时成立。** 只测一边会退化成静默失败。

### 21. ★★★ 禁止用 shell 重定向写含中文的文件
`cat >>` 追加中文会**覆盖文件开头而非追加**，并造成字节截断。
**发现信号：追加后字节数不变 —— 追加却不变大即是报警。**
⇒ 一律用 Write/Edit 或 Python 显式 encoding；诊断性只读 `python - << 'PY'` 不受影响；
若必须用 shell，写完后**必须回读验证**（字节数 + 内容位置 + 无 U+FFFD），不得信任退出码。

### 22. ★★★ 禁止在 shell/heredoc 里内联含反斜杠的正则
`\s`→`/s`、`\w`→`/w` 会被静默改写，`findall` 返回 `[]` 而目标行明明存在；**破坏时对时错**，极易被当成「偶发」放过。
⇒ ① **含反斜杠的正则一律写进 `.py` 文件（用 Write 落盘）再执行**；② 纯字面量检索在 shell 里安全；
③ **「0 命中」不是通过，是待验证** —— 先用已知会命中的样本确认检测器正常（调试第一步 `print(repr(pattern))`）。

### 23. ★ 股数双口径：新上市 / 多股份类别标的会给出两个股数
`impliedSharesOutstanding`（市值所用）与 `sharesOutstanding` 可能**差 1.71 倍**（SPCX 实测 13.182B vs 7.696B），
混用会让 PS 在 88.6 与 51.7 之间漂移。
⇒ **引用任何每股/倍数指标前，先核对 `市值 ÷ 现价` 是否等于你假设的股数。**

### 24. ★★★ 短历史标的的「伪技术指标」—— 窗口不足时数据源会**编一个看着正常的数**
上市仅 67 个交易日，yfinance 仍返回 `close_200_sma = 142.639`；**该值恰等于全部 67 日算术均值（误差 0.000）**
⇒ 所谓「200 日均线」实为「**上市以来均价**」。同类失真：「52 周高/低」实为上市以来高低；`trailingPE`/`ROE`/`Beta` 不可得。
⇒ **拿到新上市标的第一件事是数 K 线根数。指标窗口 > 可用天数时，数据源会用不足的数据算出一个看着正常的数 —— 比返回空值危险得多，因为它不触发任何缺失检查。**

### 25. ★★★ 子智能体会编造数据 —— 提示词只写「禁止编造」无效
**不是偶发，外观与真实内容完全一致**（四个角色文件曾写入证据包里没有的数字，还把未经证实的传闻当事实）。
⇒ 对策是**可执行边界**，不是道德劝告：① 列可用数字白名单；② 写明「缺数据就写『该项数据缺失』并放弃」；③ 严禁引入外部知识并举例说明禁止类型。
⇒ **复核未溯源数字的判据：能不能写出它的算式。** 写得出（如 `184.29 = 28753.29 − 28569.00`）即为派生量、正常；**写不出就是编造信号，该文件必须重做。**

### 26. ★★★ 快照字段之间的「序关系 / 恒等式」校验 —— 单字段看着都合法
MU 轮实测 4 处坏值，**全部靠字段间关系识别，而非单字段阈值**：
- **序关系**：`operatingMargins 80.37%` 同时高于 `grossMargins 72.57%` 与 `ebitdaMargins 75.57%` ⇒ 营业利润率不可能高于毛利率 ⇒ 禁用（重建约 65.4%）。
- **恒等式**：`ROE`/`ROA` 不满足杜邦恒等式（1.9112 vs 1.5285，+25.03%）⇒ ROA 禁用。
- **跨源一致**：`info.totalDebt 6.376B` 仅为报表 `15.278B` 的 **41.7%** ⇒ 不可用。
- **口径自明**：`Debt to Equity 6.33` 解为百分数差 4.46 倍、解为倍数与报表资产负债率 34.58% 矛盾 ⇒ 禁用。
- GOOG 轮补充：快照 `PB 6.894` 隐含权益 622.5B vs 报表 415.3B ⇒ PB 与快照 ROE（48.68% vs 重算 **31.83%**）分母口径均不可靠；
  快照 `Current Ratio 2.724` ≠ 报表自算 2.006；快照 `FCF 22.665B` ≠ 年报 73.3B（差 3.2 倍）；`ROA 0.1296` 对不上任何净利口径。
⇒ **通则：比率先做「序关系 + 恒等式」检验，再做数值区间检验。**（与铁律 11 同类：坏值不在区间上不越界，而在逻辑上不成立）
⇒ ⚠️ **自洽通过 ≠ 其它字段没坏**：同一份快照的三项自洽校验可能全部完美通过（市值差 −0.0000%、`PE×EPS` = 最新价），同时上面各字段全是坏的。

### 27. ★★ E 不可测量时，仓位公式保持沉默
`w* = E/(kσ²)` 在 E 未知时给出的是「**w 未知**」—— 既不产出激进派的 4%，也不产出保守派的 0%。
⇒ **两边都是把「公式沉默」误读为对自己立场的背书。**
⇒ 若要有仓位，必须由**独立于该公式**的论证支撑（Knightian 谨慎 / 几何赔率 / 硬证据组合）并显式说明来源。
- **「否定性论证」不能反向使用**：「无法证明 E>0」推不出「应当零仓位」；反之亦然。
- **「信息不足」的正确推论是「小仓位」而非「零仓位」** —— 但前提是 E 的符号**至少可测量**；**E 本身不可测量时，连「小」也没有授权。**

### 28. ★★★ 阈值型质量门槛的盲区：能同时顶高多个指标的失真
一次性税收收益（负税）会**同时**抬高净利率**和** ROE ⇒ 任何「净利率 ≥ X 且 ROE ≥ Y」的组合门槛都会放行。
**阈值越密也不管用，因为它们全被同一个项目顶高了。**
实测（S&P1500）：DUOL 有效税率 −127.0%、税收收益占净利 **56%**、报表 PE 16.0x → 正常化 **40.1x**、市值/(FCF−SBC) 29.6x；
ACAD 税率 −181.5%、占净利 **64%**、PE 12.0x → **38.6x**、**88.7x**。两只都曾是榜单前列。
**判据（已固化 `wb_analysis/_verify_earnings_quality.py`）**：
1. **税项 < 0 且「税收收益 ÷ 净利」≥ 20%** —— ⚠️ **不能用「税率是否 < 0」**（第一版把有效税率 −0.1% 的噪声也判成失真）。
2. **正常化 PE ≤ 1.2 × 报表 PE**（用各公司自己的历史有效税率中位数还原）。
3. **经营利润率与净利率的落差** —— 落差异常大说明净利不是经营赚来的。
**配套**：**拿到低 PE 先查来源，不要先当便宜证据**（查两项即可：① 税项是否为负且占净利比例大；② 经营利润率 vs 净利率的落差）。
**工具设计通则**：**硬闸门只放「事实层面确定被扭曲」的项；阈值的价值判断放软警告。误报过多的闸门等于没有闸门。**
**跨会话对同一标的作判断前，先回读该标的历史日志**（DUOL 的负税问题 9/20 已查明，9/21 因上下文压缩未回读，同一个坑踩了两次）。

### 29. ★★ `python -c "..."` 不能写含反引号的文本
本机是 bash；`python -c "长文本"` 时文本里的**反引号会被 shell 当成命令替换**，内容被展开成空串而**静默丢失**
（实测一段约 11,000 字的记忆被削到 2,822 字，且不报任何错）。
⇒ **写含反引号 / `$` / 反斜杠的文本，一律用「Write 工具落盘 .py 脚本 → 执行脚本」两步走**，不要用 `bash -c` 内联。
同理适用于写报告、补丁、配置文件。（与铁律 21、22 同源：**含特殊字符的文本不要内联进 shell**。）

### 30. ★★★ 财报科目的「独立第三方核验」必须打到 SEC 原值，且要过三关（2026-09-22 立）
用户要求「财报基本面都要数据来源精准」时的标准做法：**yfinance 的报表 ≠ 权威**，要用 **SEC EDGAR（10-K 原值）** 对账。
但直接照抄会踩三个坑：

| 坑 | 现象 | 处置 |
|---|---|---|
| ① **项目内缓存是精简过的** | `edgar_fundamentals.fetch_facts()` 返回的是 `slim_facts()` 的结果，**`us-gaap` 只保留 8 个标签**（Assets / Liabilities / Revenues / NetIncomeLoss / StockholdersEquity / CommonStockSharesOutstanding / WeightedAverageNumberOfDilutedSharesOutstanding / NetIncomeLossAvailableToCommonStockholdersBasic）⇒ **营业利润 / 毛利 / EPS / 经营现金流 / 资本开支 / 长期债务 全都取不到** | **直连 `data.sec.gov/api/xbrl/companyfacts/CIK##########.json`**（`wb_analysis/_verify_edgar_raw.py`，带 24h 本地缓存） |
| ② **期间不对齐 ⇒ 假差** | 证据包 §4 的列是「最新期在前」；若取「最新 instant」会落到**下一个季度末**（NFLX 实测取到 2026-06-30，而目标是 FY2025 的 2025-12-31）⇒ 出现 **−4.88%（总资产）/ −11.73%（权益）的假差** | **锁定期末日**（`end == 目标期末`），并筛 `form=10-K`、`fp=FY` |
| ③ **现金流符号约定** | SEC 对 `PaymentsToAcquirePropertyPlantAndEquipment` / `PaymentsForRepurchaseOfCommonStock` 报**正的绝对流出额**，而报表记负 ⇒ 只看数值会得 **−200% 的假差** | 判据写成 `\|a\| ≈ \|b\|`，命中即判「一致（仅符号约定差异）」 |

⇒ **判据**：`wb_analysis/_verify_edgar_raw.py` 输出的「一致 / 不一致 / SEC 无标签」三态。
**实测（NFLX FY2025）**：营收 / 营业成本 / 营业利润 / 净利 / 税前 / 稀释 EPS / 总资产 / 权益 / 长期债务 / OCF / Capex / 回购
**12 项与 SEC 完全一致**（其中 2 项为符号约定差异，金额分毫不差），共同申报日 2026-01-23。
⇒ **凡报告要引用财报数字，先确认它有没有过 SEC 这一关；过不了的必须标注「单一来源、未经 SEC 核验」。**
⇒ 注意：**「总债务」在 XBRL 里没有单一标签**，只能由「长期债务（非流动）+ 流动部分」自算 ⇒ 引用时须声明为**派生量**。
⚠️ **本条只管「打到原值」；同一模块的派生字段会骗人 —— 见铁律 38**（`get_point_in_time()` 的伪 TTM）。
⇒ 反面配套：**验完之后仍要报告「跨源 TTM 不一致」**（NFLX 实测 yfinance TTM 营收 48.371B vs EDGAR 47.399B，差 −2.0%；
TTM 净利 13.650B vs 14.357B，差 −4.9%，两源 TTM 窗口不同）⇒ **引用 TTM 必须写明取自哪个源，不得混合。**

### 31. ★★ 目录 mtime 不可作时间锚点；两段计划不可共享同一快照（2026-09-23 立）
清理 `reports/` 时一次踩到两个坑，都属于「看着对、其实错」：

**① 目录 mtime 会在「往目录里写文件」时被刷新。**
重排报告用的是「逐文件 `shutil.copy2` + 删源」而不是目录级移动（本机 safe-delete 钩子会拦目录移动）。
`copy2` **保留文件 mtime**，但**新建目录、往目录写文件都会把目录自己的 mtime 刷成当前时刻**。
⇒ 于是所有报告树的目录 mtime 都变成了「重排时刻」，用 `tree.stat().st_mtime` 去关联「哪批草稿属于它」
   时**全部错配到最新的草稿**（实测 `GOOG_20260918_090415` 被错配到 2026-09-21 的草稿）。
⇒ **判据**：时间锚点一律取**文件**的 mtime（优先 `complete_report.md`，因为 `copy2` 会保留它），
   取不到再退到「树内最早文件的 mtime」。**永远不要用目录 mtime 做时间判断。**
（与铁律 7 同源：mtime 不可信，能内容比对就内容比对；此处无法比对，则改用「被保留的文件 mtime」。）

**② 两段执行计划若共享同一时刻的快照，后一段会看见前一段的产物。**
`_reorg_reports.py` 原本「先搬报告树、再处理散落条目」。报告树被搬进 `reports/<标的>/` 后**产生了新目录**，
而第二段的计划是在**运行开始时**算好的 —— 但它把刚生成的 `reports/DUOL`、`reports/GOOG`、`reports/GLD`
当成了「非 12 角色的专题目录」又扫进了 `_other/`，**三个标的的目录被误挪**。
⇒ **判据**：**把「会产生新目录/新文件的那一段放到最后执行」**，从结构上消除该失效模式；
   并加**幂等护栏**（源不存在即跳过）+ **事后布局断言**，不依赖「小心一点」。

**④ 带提权的命令可能被执行两次** ⇒ **所有破坏性工具必须幂等**。
实测：`_reorg_reports.py` 第二遍扫到了第一遍刚生成的目录（3 个标的被误挪）；
`_cleanup_reports.py` 两遍产生了两个内容不同的回滚包（134 条 / 183 条），一度让我误判「回滚包不完整」。
⇒ 处置：① 把「会产生新目录/新文件的那一段放到最后」；② **幂等护栏**（目标已存在就补齐而不是重做）；
③ **事后布局断言**。**不要依赖"命令只跑一次"。**

**⑤ 保留策略必须「按类别」，不能「全局取最新 N 个」。**
实测：给 `.workbuddy/backup/` 写「只留最近 3 个」，结果**把最大的那个回滚包（1.35 MB、覆盖 134 个文件）
挤掉了，却留下两个内容完全相同的重复包**（双执行产物）。
⇒ 判据：保留策略按**前缀**分组各留 N 个（`deleted_*` / `duptrees_*` / `orphans_*`），并**按内容哈希去重**。
⇒ 工具：`scripts/_prune_backup.py`。
⇒ ⚠️ **修正一条旧结论**：此前日志里写「回滚包只装了 134/183 条、不完整」是**误判**——
回收站里同时存在一个 **183 条目的完整包**（那是第一遍执行的产物）。已恢复为
`.workbuddy/backup/deleted_20260923_FULL183.zip`。⇒ **教训：在宣布「备份不完整」之前，先去看回收站**。

**③ 顺带一条备份铁律**：删除类工具的「先打包再删」必须**校验压缩包内容与清单逐项一致，不一致就中止**。
实测一次删除里压缩包只写进了 134/183 条而删除照常执行 ⇒ **回滚包静默地不完整**。
「备份看着有、其实是残的」比没有备份更危险，因为它只在真正要回滚时才暴露。

## 契约与校验器的硬约束

### ★ `trader.md` 的契约 = 结论块首行 `**Action**` + 末行 PROPOSAL（2026-10-08 校正）
```
结论块首行：**Action**: <Buy|Hold|Sell>          ← Title Case，_gen_meta.py 正则**大小写敏感**
            **Reasoning**: ...                    ← 其后
            **Entry Price** / **Stop Loss** / **Position Sizing**   ← 可省略；含价格须为**绝对数字**
末行：      FINAL TRANSACTION PROPOSAL: **<HOLD>**   ← **大写**，串全文恰 1 次
```
- ⚠️ **两处大小写规则相反**：结论块用 `Sell`（Title Case，否则 `_gen_meta.py` 提取不到 `trader_action`），末行用 `**SELL**`（大写，`_check_role_files.py` 的 `THREE` 只认大写）。（实测踩坑：2026-10-08 WDC 轮，写成 `**Action**: SELL` ⇒ `_gen_meta` 报「未找到结论块标签」。）
- ⚠️ **原本节写作「首行 Reasoning」，是漂移**。以 `FRAMEWORK.md` §Ⅲ 与 `_lint_drafts.py` 的注释为准：**块以 `**Action**` 打头**。
  `_lint_drafts.py` 找 `head` = **首个以 `**Recommendation**` / `**Rating**` / `**Action**` 开头的行**，
  然后只允许 `head + slack`（manager/PM/风险席位 3 行，**trader 5 行**）内的五档词 ⇒ **打头标签写错会让容差窗口错位**。
- `_verify_report.py` 校验**末行**必须以 `FINAL TRANSACTION PROPOSAL` 开头
- `_lint_drafts.py` 要求该串**恰好 1 次**，且形如 `... : **(BUY|HOLD|SELL)**`
- ⚠️ **正文不得再出现该串**，包括「本报告不写 FINAL TRANSACTION PROPOSAL」这类声明（会被标为「仅提到」，不阻断）
- ⚠️ **正文（含表格）不得出现 `BUY`/`HOLD`/`SELL` 等英文档位词**：`_lint_drafts.py` 的 `RATING_RE` **同时匹配大写**，

### 32. ★★ 缺数据不可怕，**缺口没被下游看见**才可怕（2026-09-23 立）

**③ 有决定性缺口时，结论必须是**条件式**，不能是静默降级。**

### 33. ★★ 代码搬家的五条安全规程（2026-09-23 立，全部来自实测踩坑）

| # | 坑 | 症状 | 规程 |
|---|---|---|---|
| ① | **先写盘后校验** | 校验失败时**坏文件已经落盘**，还得手工清 | **先 `ast.parse` 校验，再写盘** |

### 34. ★★★ 缓存按本机时区判「当日」⇒ 跨时区分析时当日缓存永不刷新（2026-09-24 立，已修）

上游 `stockstats_utils._needs_same_day_refresh` 拿 `pd.Timestamp.today()`（本机）去比 `curr_date`
⇒ `curr_date < today` **恒真** ⇒ 判据恒返回 False ⇒ **当日缓存永不刷新**。

**实测后果（本轮真踩）**：9/23 收盘后 4.8 小时首次采集时，日线 bar 还只有 Volume、OHLC 全 NaN，

|---|---|---|
| RSI | 55.19 | **45.00** |
| MACD 柱 | 1.905 | **1.014** |
| ret_5d / 20d / 60d | +1.75% / +0.88% / +3.87% | **−1.29% / −2.37% / −4.58%** |

⇒ **收益率三项直接翻号、RSI 从中性偏强变中性偏弱 ⇒ 结论方向被改写。**
**修复**：新增 `_market_today_eastern()`，把本机时间换算到 **US/Eastern** 再判。
⚠️ **必须经 `pd.Timestamp.today()` 换算**（该入口会被测试桩掉以注入固定时钟）；

### 38. ★★★ `edgar_fundamentals.get_point_in_time()` 会返回**伪 TTM** —— 它拼的是「前 9 个月 + 上一财年 Q4」（2026-10-08 立）

**症状**：该函数返回的 `net_income_ttm` / `revenue_ttm` **既不是滚动 12 个月，也不对应任何真实财年**，
但它的字段名与结构（`*_ttm` + `*_filed`）**看起来完全正常**，而且 `filed` 日期可能落在**基线日前一天**，
极易被当成「基线日前一天有新申报」而写进结论。**这是铁律 3「静默失败」在派生字段上的变体。**

**实测（WDC，基线 2026-10-06，采集 2026-10-07）**：
```

  → net_income_ttm = 6,511.0M   net_income_filed = '2026-10-05'
  → revenue_ttm    = 11,777.0M  revenue_filed    = '2026-08-14'
```
反推拆解（**这一步就是本条的全部方法**）：
| 伪 TTM | 拆解 | 校验 |
|---|---|---|
| `6,511` | `6,229`（FY2026 前 9 个月，10-Q）+ `282`（FY2025 Q4，10-K） | ✓ 精确 |
| `11,777` | `9,172`（FY2026 前 9 个月）+ `2,605`（FY2025 Q4） | ✓ 精确 |
⇒ 它**无视了 2026-08-14 已申报的 FY2026 10-K**（营收 12,919.0M / NetIncomeLoss 9,424.0M）。

**另一处连带误解**：`filed = 2026-10-05` 那份申报是 **`DEF 14A`（委托投票书）**，
内容仅为历史财年汇总（FY2022 1,546 / FY2023 −902 / FY2024 −765 / FY2025 1,643 / FY2026 9,424），**无新信息**。
⇒ **「有新申报」不等于「有新数据」。**

**⇒ 判据（识别法）**：拿到任何 `*_ttm` 派生字段，**先用它的分项反推能否拼成一个完整财年**。
拼不成 / 拼出来对应不上任何 `end` 日期 ⇒ **判为伪 TTM，禁止引用**。
同时用「遍历全部 `us-gaap` 事实、列出目标日之后所有 `filed` 日期 + form」来确认**到底有没有新申报**
（实测：2026-07 之后只有 `2026-08-14 10-K` 与 `2026-10-05 DEF 14A` ⇒ 无 Q1 10-Q ⇒ 该季度**确实不可得**）。

**⇒ 配套的两条口径纠正（同一轮实测）**：
1. **财年截止日不要用 yfinance 的列标签**。WDC 用 **52/53 周财年**，yfinance 标 `2026-06-30`，
   而 SEC 10-K 的实际期末是 **`2026-07-03`** ⇒ 滞后基线应为 **95 天**，不是 98 天。
   **引用「某年年报」时，一律以 SEC 的 `end` 为准，并注明 yfinance 标签。**
2. **分季度数据可以从 10-Q 期段事实直接取**，且**必须做「加总自洽」校验**（Q1+Q2+Q3 == 10-Q 报的前 9 个月；再加 Q4 == 10-K）。

### 40. ★★★ 与 28 同族但**机制不同**：**未实现公允价值重估**会把报表 PE 打到真实值的一半以下（2026-10-08 立，GOOG 事件）

### 41. ★★★ 「**拿到的是空内容**」与「**调用抛了异常**」是两种失败；只拦后者 = 健康度假绿（2026-10-08 立，GOOG §5/§6 事件）

**症状**：采集报告「32 / 35 通道成功」，但打开证据包，**§5 个股新闻整节只有一行

**根因（两个独立缺陷叠加，必须分开修）**：

1. **健康度判据漏了「空态串」**（`wb_analysis/collect.py::_safe_call`）。

   ⇒ 这与 2026-09-17 修 StockTwits 假绿是**同一漏洞的另一面**：
   **那次是「失败返回占位串」，这次是「失败返回自然语言空态」。**

2. **上游两条新闻通道都不保证正文**（`tradingagents/dataflows/yfinance_news.py`）：
   - `Ticker().news` / `.get_news()` —— 条目嵌套在 `content` 里、**含 `summary`**，

- **`_PLACEHOLDER_MARKERS` 增加 `no news found for` / `no global news found`**。
  ⚠️ 匹配串必须**足够长**：测试里 `"…there is No global news that matters…"`（真内容）
  **不得**被误伤 —— 已做**双边夹具**（空态串 → unavailable；真内容 → ok），
  脚本 `scripts/_oneoff/_verify_placeholder_markers.py`。
  ⇒ 修后健康度由 **32/35（假绿）→ 31/35（如实）**，非全绿通道多出 `get_news=unavailable`。
- **新增按需正文回填**（`backfill_missing_summaries()` + `_extract_body_from_html()`）：
  抓新闻页 → **限定 `article-body` 容器**取 `<p>`；上限 8 篇、单篇截断 1,200 字符、
  失败**静默降级**（保留标题、不中断采集）。
  ⇒ GOOG §6 由「节长 1,605 / **正文 0**」→「节长 8,661 / **正文 7,053**」，

1. **通道健康度不能只看「是否抛异常」**。凡「失败时返回可读字符串」的通道，

### 42. ★★★ 「精确勾稽 / 已验证 / 已核实」这类**验证断言**不可跨报告直接引用 —— 必须自行复算（2026-10-08 立，UBER 轮三方互纠事件）

**症状（UBER 轮真实发生）**：
1. 基本面分析师在**回报消息**里写「本报告 §1.1 的链条已用四年数据验证，**会计恒等式精确勾稽（残差为 0）**」。
2. 市场分析师**在自己报告里复制了这个措辞**，未复算。
3. 市场分析师随后**自查发现该断言为假**：四年残差为 **−93 / −27 / −221 / +104M**，**方向不统一** ⇒ **「税前 − 税项 = 净利」不是精确恒等式**（存在未披露项：非控股权益、权益法投资收益等）。
4. 基本面分析师复核后澄清：**报告正文本身没错**（链 C「营业利润 → 税前」残差确为 0），**错的是消息措辞**用「会计恒等式」把两步混为一谈。

**根因（比错误本身更重要）**：
- **验证断言是「结论」，不是「数据」。** 数据可引用来源，**结论必须复算**。
- 「已验证 / 精确勾稽 / 残差为 0 / 分毫不差」在跨角色、跨报告、跨会话传递时**会失真**，因为**传递的是措辞而非算式**。
- ★ **铁律 25 只覆盖「数字」，不覆盖「验证断言」** —— 这是既有规则的覆盖盲区。

**⇒ 判据（新增）**：
1. **凡引用他人报告中的「已验证 / 精确勾稽 / 残差为 0 / 分毫不差」，必须自行复算再落盘**；复算不通过时**先怀疑断言、再怀疑数据**（本例数据对、断言错）。
2. **写验证断言必须同时写出算式与残差**（例：`5,565 + 303 − 68 = 5,800 = 税前，残差 0`）。**只写「已验证」不写残差的断言等于没有断言。**
3. **「会计恒等式」与「逐步勾稽」必须分清**：前者要求残差恒为 0；后者允许存在方向已披露的未披露项。**混淆二者会让「残差 0 的一步」被误读为「整条链都是恒等式」。**
4. **最不利情形检验**：若结论依赖可能不精确的分母，必须算出**分母向不利方向偏移后的结论**（本例税盾 4,346M → 4,253M ⇒ 占比 **42.31%**，仍远超 20% 硬线 ⇒ **核心结论不变**）。**⇒ 这一步把「算术精度问题」与「结论方向问题」分开。**

**★ 与「多 agent 交叉复核」的关系（第二例印证）**：
- AVGO 轮：子智能体抓到**主流程的流动比率算错**（0.705 → 1.705）。
- UBER 轮：市场分析师抓到**基本面分析师的验证断言不成立**，**随后自查发现自己也复制了同一措辞**。
- ⇒ **交叉复核的价值不止于「抓到别人的错」，还在于「抓到后自查是否自己也复制了」。**

**⇒ 与铁律 30 的分工**：30 管**数据来源**（引用财报数字要打到 SEC 原值）；**本条管验证结论的传递**。两者都不可省。
